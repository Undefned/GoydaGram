## Сравнение БД по характеристикам

---

### 1. PostgreSQL

| Характеристика | Оценка | Комментарий |
|---------------|--------|-------------|
| **Скорость чтения** | ⭐⭐⭐⭐ | С индексами — быстро, без индексов — медленно |
| **Скорость записи** | ⭐⭐⭐ | Медленнее NoSQL, транзакции тормозят |
| **Надёжность** | ⭐⭐⭐⭐⭐ | ACID, данные не потеряются |
| **Масштабирование (вертикальное)** | ⭐⭐⭐⭐ | Добавил RAM/CPU — стало быстрее |
| **Масштабирование (горизонтальное)** | ⭐⭐ | Шардирование сложное (Citus, Patroni) |
| **Сложность настройки** | ⭐⭐⭐ | Средняя, но требует опыта |
| **Потребление памяти** | ⭐⭐⭐ | Буферный кеш использует RAM |
| **Лучше всего для** | Транзакции, JOIN, строгая схема, малый-средний объём данных |
| **В твоей архитектуре** | User Service (пользователи, подписки), Video Service (метаданные видео) |

---

### 2. MongoDB

| Характеристика | Оценка | Комментарий |
|---------------|--------|-------------|
| **Скорость чтения** | ⭐⭐⭐⭐ | Быстро по ключу (_id) и индексам |
| **Скорость записи** | ⭐⭐⭐⭐⭐ | Очень быстро, нет сложных проверок |
| **Надёжность** | ⭐⭐⭐ | Транзакции есть, но медленнее PostgreSQL |
| **Масштабирование (горизонтальное)** | ⭐⭐⭐⭐⭐ | Шардирование из коробки (ключ шарда — video_id) |
| **Сложность настройки** | ⭐⭐⭐ | Средняя |
| **Потребление памяти** | ⭐⭐ | Денормализованные данные весят больше |
| **Лучше всего для** | Высокая нагрузка на запись, гибкая схема, миллионы документов |
| **В твоей архитектуре** | Social Service (лайки, комментарии) |

---

### 3. Redis

| Характеристика | Оценка | Комментарий |
|---------------|--------|-------------|
| **Скорость чтения** | ⭐⭐⭐⭐⭐ | Микросекунды, 100k+ операций/сек |
| **Скорость записи** | ⭐⭐⭐⭐⭐ | Микросекунды |
| **Надёжность** | ⭐⭐ | Без AOF/RDB теряет данные при падении |
| **Масштабирование (горизонтальное)** | ⭐⭐⭐⭐ | Redis Cluster — шардирование по ключам |
| **Сложность настройки** | ⭐⭐⭐⭐ | Простая, 1 файл конфигурации |
| **Потребление памяти** | ⭐⭐ | Всё в RAM, дорого |
| **Лучше всего для** | Кеш, счётчики, очереди, реальное время |
| **В твоей архитектуре** | Кеш профилей, лента (активные пользователи), счетчики лайков, rate limiting |

---

### 4. Cassandra

| Характеристика | Оценка | Комментарий |
|---------------|--------|-------------|
| **Скорость чтения** | ⭐⭐⭐⭐⭐ | Быстро по ключу партиции (user_id) |
| **Скорость записи** | ⭐⭐⭐⭐⭐ | Очень быстро, append-only лог |
| **Надёжность** | ⭐⭐⭐⭐⭐ | Репликация по нескольким нодам, нет SPOF |
| **Масштабирование (горизонтальное)** | ⭐⭐⭐⭐⭐ | Линейное — добавил ноду, увеличилась пропускная способность |
| **Сложность настройки** | ⭐⭐ | Высокая — консистенция, стратегия репликации |
| **Потребление памяти** | ⭐⭐⭐ | Нет, данные на диске, но есть memtable |
| **Лучше всего для** | Лента пользователей (user_feed), временные ряды, миллиарды записей |
| **В твоей архитектуре** | Идеальна для Feed Service (лента), но не взяла из-за сложности |

---

### 5. ClickHouse

| Характеристика | Оценка | Комментарий |
|---------------|--------|-------------|
| **Скорость чтения (аналитика)** | ⭐⭐⭐⭐⭐ | Миллиарды строк агрегируются за секунды |
| **Скорость записи (одиночная)** | ⭐⭐ | Медленно, не для OLTP |
| **Скорость записи (батчами)** | ⭐⭐⭐⭐⭐ | Тысячи строк в секунду |
| **Надёжность** | ⭐⭐⭐⭐ | Репликация есть |
| **Масштабирование (горизонтальное)** | ⭐⭐⭐⭐⭐ | Шардирование из коробки |
| **Сложность настройки** | ⭐⭐ | Высокая |
| **Потребление памяти** | ⭐⭐⭐⭐ | Хорошее сжатие (5-10 раз) |
| **Лучше всего для** | Аналитика, агрегации, большие данные (OLAP) |
| **В твоей архитектуре** | История просмотров (аналитика), не для основного сервиса |

---

### 6. Elasticsearch

| Характеристика | Оценка | Комментарий |
|---------------|--------|-------------|
| **Скорость полнотекстового поиска** | ⭐⭐⭐⭐⭐ | Миллисекунды по миллиардам документов |
| **Скорость точного поиска (по ID)** | ⭐⭐⭐⭐ | Быстро, но медленнее Redis |
| **Скорость записи** | ⭐⭐⭐ | Требует индексации (асинхронно) |
| **Надёжность** | ⭐⭐⭐⭐ | Шардирование + реплики |
| **Масштабирование (горизонтальное)** | ⭐⭐⭐⭐⭐ | Добавил ноду — быстрее |
| **Сложность настройки** | ⭐⭐ | Высокая, много параметров |
| **Потребление памяти** | ⭐⭐ | Ест много RAM и CPU |
| **Лучше всего для** | Поиск (Google-like), логи (ELK stack) |
| **В твоей архитектуре** | Search Service (поиск по тегам и описанию) |

---

### 7. SQLite

| Характеристика | Оценка | Комментарий |
|---------------|--------|-------------|
| **Скорость чтения** | ⭐⭐⭐⭐ | Быстро для маленьких данных |
| **Скорость записи** | ⭐⭐⭐ | При конкурентных запросах — блокировки |
| **Надёжность** | ⭐⭐⭐⭐ | ACID, но только один процесс пишет |
| **Масштабирование (горизонтальное)** | ⭐ | Нет, только один файл |
| **Сложность настройки** | ⭐⭐⭐⭐⭐ | Очень просто — нет сервера |
| **Потребление памяти** | ⭐⭐⭐⭐⭐ | Минимальное |
| **Лучше всего для** | Встроенные приложения, мобильные, тесты |
| **В твоей архитектуре** | Кеш ленты на фронтенде (Service Worker), не для бекенда |

---

### 8. MinIO (не БД, объектное хранилище)

| Характеристика | Оценка | Комментарий |
|---------------|--------|-------------|
| **Скорость чтения** | ⭐⭐⭐⭐ | 10+ Гбит/с в продакшене |
| **Скорость записи** | ⭐⭐⭐⭐ | Зависит от дисков |
| **Надёжность** | ⭐⭐⭐⭐⭐ | Erasure coding, репликация |
| **Масштабирование (горизонтальное)** | ⭐⭐⭐⭐⭐ | Distributed mode |
| **Сложность настройки** | ⭐⭐⭐ | Средняя |
| **Потребление памяти** | ⭐⭐⭐⭐ | Низкое |
| **Лучше всего для** | Видео, изображения, файлы, совместим с S3 |
| **В твоей архитектуре** | Видео и изображения |
